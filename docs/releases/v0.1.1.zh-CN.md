# v0.1.1 · GitHub Pages 发布

**简体中文** | [English](v0.1.1.en.md) | [v0.1 完整介绍](v0.1.0.zh-CN.md)

## 新增

- 在服务器连接中切换 SFTP/SSH 或 GitHub Pages。
- 为公开的 `用户名.github.io` 主页仓库配置、测试并加密保存访问令牌。
- 上传构建后的网站到 `fuwari-pages` 分支，保留 Git 提交历史；尝试开启 Pages 并触发部署。
- “检查上线状态”按钮，对照本次提交查询 Pages 构建结果。
- 专用 GitHub 配置说明、上传文件大小和数量限制，以及远程分支更新冲突检查。

## 调整与修正

- 发布状态区分“已提交、等待 Pages 部署”和“已上线”，避免把文件提交成功当作上线成功。
- 连接资料返回界面时过滤令牌；同一仓库留空可保留已保存令牌，切换仓库不能复用旧令牌。
- 本地运行环境目录更新到 `0.1.1`，加载对应版本的管理端。

以上为新增 GitHub 流程中的处理；没有证据表明本版本修复了独立的 v0.1 SFTP 或预览缺陷。

## 已知问题与范围

- GitHub 可能返回 Pages 启动 403，而网站文件已经提交。确认仓库 Settings → Pages 使用 `Deploy from a branch`、`fuwari-pages`、`/(root)`，再到 Actions 查看构建。当前错误信息未区分开启 Pages 与触发构建失败。
- 多预览实例的 Astro 缓存写入冲突尚未修复。
- 仅支持 GitHub.com 公开主页仓库；不支持项目子路径、自定义域名、私有仓库或 Enterprise。
- GitHub 保存的是静态网站历史，不是 Markdown 源码及草稿备份。
- 软件界面仍为中文；本次提供的是中英文项目文档。

## 升级

先备份本地项目，退出旧程序，将新版本解压到新文件夹，用“项目 → 打开已有博客”选择原项目。连接凭据可能需要在新版重新填写；不要删除旧数据目录。安装包仍不带代码签名。
